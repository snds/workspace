`dispatcher-w2-1.patch` (W2-1, H11 follow-up): at SessionEnd the dispatcher commits and pushes, and the report-only pre-push gate could wait up to ~20 s for the post-commit verify of that same tree (the dispatcher's own record covers only the rebuild, not a verify). Two changes. The push runs with `WS_GATE_NOWAIT=1`: the gate (`09-tools/git_lanes.py`, changed in the same commit) then reuses a recorded verdict for the tree, or detaches the verify and lets the push go at once; the tree is still verified exactly once and its verdict lands in `last-gate.json`, where the card and the stop hooks read it. Under `ws.pushgate = block` the variable is ignored and the push waits for the verdict as before. And `_write_last_gate` merges its `nightly` field into `last-gate.json` instead of overwriting it, so the gate's `gate`/`ring` records survive SessionEnd (a `gate` for an older tree is dropped from the top level only; the ring keeps it).
Apply from the workspace root once git_lanes.py is re-pinned: `git apply --check 00-bootstrap/patches/dispatcher-w2-1.patch && git apply 00-bootstrap/patches/dispatcher-w2-1.patch`, then `python3 .claude/hooks/dispatcher.py --self-test` and commit. Before the re-pin the variable is simply unknown to the pinned gate, so applying early is harmless.
