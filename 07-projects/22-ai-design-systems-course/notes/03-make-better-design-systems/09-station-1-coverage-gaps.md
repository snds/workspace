# Station 1: Coverage & Gaps

Does the system have what *your* products need, in design + code + docs?

Typical light: missing meat-and-potatoes components/variants everyone else has; uneven stool (in code not Figma, or vice versa); half-baked tokens; thin docs (org-level a11y/i18n *and* component anatomy/API/when-to-use/product context).

AI: gap analysis from the three assets, then fill — generate component/variant, translate design↔code, generate docs. Demos next. Timestamped tooling; principles outlast the specific MCP.
