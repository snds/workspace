# Program thesis

**LCARS is the proving ground, not the ceiling.**

If we can faithfully and accurately recreate LCARS in concept, context, intent, and aesthetic — systemically and programmatically — the same stack can target other surfaces, aesthetics, and design systems. Faithful LCARS is the hard exam. Passing it proves the method generalizes.

## What "systemic and programmatic" means

| Layer | Owns | LCARS instance | Other system later |
|---|---|---|---|
| **Intent + context** | Who / why / workflow; role; query | Combadge roles, research recipes | Different roles, domains |
| **Concept** | Interaction model; what the surface *is for* | Console answers by recomposing, not chat | Same pattern or domain-specific |
| **Construction grammar** | Measured frame graph, segments, type, motion locks | Okudagram elbows, spines, gutters | That system's chrome grammar |
| **Tokens + constitution** | Legal fills, contrast, density, motion | LCARS ramps + APCA floors | That system's tokens + rules |
| **Scene IR → renderer** | Typed assemblies → deterministic pixels | Current catalog + validator | New pack; same IR pipeline shape |
| **Fidelity prove** | Named northstar + cue matrix + measurement | S-SYS47-01 Literal | New S-IDs under same contract |

The transferable product is the **pipeline and IR shape**, not a pile of LCARS CSS. System-specific knowledge lives in a **system pack** (grammar + tokens + catalog + northstars). Swap the pack; keep the method.

## Four fidelity axes (all required for "faithful")

1. **Concept** — correct product model (what kind of thing this UI is)
2. **Context** — correct situational assembly (role, intent, data)
3. **Intent** — correct communicative job of each region via **content groups** (`focal.viewport`, `support.bay`, `footer.supplement`, … — see `docs/content-groups.md`)
4. **Aesthetic** — measured look: geometry, color, type, motion locks

Spirit vibe-match on (4) alone is a Fail for the proof program. Literal aesthetic without (1)–(3) is also incomplete for the generative product.

**Topology matters:** MSD dual opposing spines (T2) must not be forced into a classic left-rail shell (T3).

## Proof ladder

1. **Literal still** — one complex reference screen Matches Literal (cue matrix)
2. **Programmatic** — same screen expressed as Scene IR + catalog primitives (not one-off CSS)
3. **Generative under grammar** — recipes recompose *other* legal surfaces that still obey the pack
4. **Pack transfer** — second aesthetic pack proves the pipeline is not LCARS-hardcoded

Do not claim (4) until (1)–(3) exist for LCARS.
