# Integrations and dependencies

**TL;DR:** Synapse connects to three groups. **Providers** are the accounts you hold: GitHub, Linear and Atlassian. **Consumers** are the tools and agent apps that need those accounts. **Foundations** are the operating systems, your Unraid server and the signing services. Each group has a risk, and each risk has a planned answer, listed at the end.

## Providers (where your accounts live)

### GitHub

| Use | How |
|---|---|
| git over HTTPS | Token from the credential helper |
| git over SSH | Per-identity key through the `sy ssh` wrapper |
| `gh` CLI | Token in `GH_TOKEN` for that one call |
| Health checks | REST API: who am I, token permissions, expiry |
| Agents | GitHub's MCP server, started locally with the token, or the hosted one with a bearer token |

**Ways to sign in** (each identity picks one or more):

1. **A GitHub App you register for yourself, using device flow.** You enter a short code in the browser. Tokens expire after 8 hours and refresh automatically, with fine-grained permissions. This is the best choice for personal accounts.
2. **Import from a `gh auth login`.** Synapse runs it in a private, throwaway config, keeps the token, then clears the throwaway copy. It uses the GitHub CLI's own app, which many employer orgs already allow. The token is long-lived and broad, so Synapse tracks it and reminds you to rotate it.
3. **Fine-grained personal access token**, pasted once into the app.
4. **SSH key per identity**, generated by Synapse or imported.

**Employer accounts:** orgs can block third-party apps, require approval for fine-grained tokens, and require SSO authorization for tokens. Options 2 and 3 usually work within those rules. Synapse checks SSO authorization as part of its health checks.

### Linear

| Use | How |
|---|---|
| Agents | Linear's hosted MCP server at `https://mcp.linear.app/mcp`. It supports OAuth 2.1 with dynamic client registration, which needs no app setup. It also accepts an API key or OAuth token as a bearer header. |
| Health checks | GraphQL API: viewer, organization |

Two Linear workspaces become two identities. The gateway picks one per project. Most agent apps can't do this on their own, because they key the connection on the server URL.

### Atlassian (Jira, Confluence)

| Use | How |
|---|---|
| Agents | Atlassian's Rovo MCP server. Its main method is OAuth 2.1. API tokens work only if an org admin has enabled them, and some tool sets, such as Jira Service Management and Bitbucket, are API-token only. |
| Health checks | REST API with the same credential |

The older SSE endpoint stopped being supported after 30 June 2026. The gateway uses the current endpoint and treats the URL as config, not code.

### Later providers

GitLab, Bitbucket, Azure DevOps, Asana, Notion, Slack and package registries such as npm. They start through the generic `sy run` injector with secret references. A provider gets its own module only when it needs sign-in or health checks.

## Consumers on each device (tools)

| Tool | Minimum | How Synapse connects | Notes |
|---|---|---|---|
| git | 2.36 | `credential.helper` for configured hosts, `credential.useHttpPath = true` so git sends the repo path, `includeIf "hasconfig:remote.*.url:…"` for commit identity, `core.sshCommand` for SSH | git 2.36 added the `hasconfig` condition |
| Git for Windows | current | Takes over only the configured hosts from Git Credential Manager and leaves the rest alone | GCM stays installed |
| `gh` | 2.40 | Shim sets `GH_TOKEN` per call | 2.40 added multi-account. Synapse doesn't rely on it, but Watch reads it. |
| OpenSSH | built in | `core.sshCommand = sy ssh` picks the key and forces `IdentitiesOnly` | Windows has two ssh programs (Windows' own and Git for Windows' copy). The wrapper names one explicitly. |
| Other CLIs | any | `sy run` with secret references | Replaces `op run` from 1Password |

## Consumers on each device (agent surfaces)

| Surface | How Synapse connects | Coverage |
|---|---|---|
| Claude Code (terminal and desktop Code tab) | Shell commands inherit the shims and git config. MCP entries point at `sy mcp …`. | Full |
| Claude desktop app (chat) | MCP entries in its config file. A packaged desktop extension is possible later. | MCP only |
| Cursor (local agent and terminal) | Shims, git config, `mcp.json` | Full on the device |
| Cursor background or cloud agents | Run on Cursor's servers | Inventory only |
| VS Code + Copilot | Terminal and tasks use the shims. MCP through VS Code's `mcp.json`. | Copilot's own GitHub sign-in is managed by VS Code: checked, not routed |
| Codex CLI | `config.toml` MCP section + shell | Full |
| Gemini CLI | `settings.json` MCP section + shell | Full |
| Windsurf, Zed, Warp | Their MCP config files + shell | Expected full; confirmed per app in Phase 3 |
| claude.ai connectors, ChatGPT connectors, Claude Code on the web, Copilot coding agent | Sign in on the vendor's servers | Inventory and reminders only |

**Shared surface catalog.** The workspace generator (`wsx scan`, project 18) already detects most of these apps. Both tools should read one catalog file, `surfaces.json`. It lists where each app keeps its config on each OS, the config format, how to verify the connection, and how far Synapse can reach. Adapters are mostly data, which makes vendor changes quick to fix.

## Foundations: operating systems

### macOS (13 Ventura or later)

- **Keychain Services**, data protection keychain with an access group, so only Synapse's signed programs can read its items. Items are marked "this device only," so they never sync to iCloud and never restore to another Mac.
- **Secure Enclave** for the device key and for wrapping vault keys. It holds P-256 keys only, which sets the key type.
- **LocalAuthentication** for Touch ID or password checks.
- **SMAppService** to register the daemon and the app at login.
- **UserNotifications** and the menu bar, through Tauri.
- **Unix domain sockets** with the caller's audit token, plus code-signing checks.
- **Apple Developer Program** (paid yearly) for Developer ID signing, notarization and keychain access groups.

### Windows (10 22H2 or 11)

- **TPM 2.0 through CNG** (the Microsoft Platform Crypto Provider) for non-exportable keys.
- **DPAPI and Credential Manager** as fallbacks.
- **Windows Hello** for presence checks and to unlock the employer key.
- **Task Scheduler** for a per-user logon task.
- **Named pipes** with an access list for your account only, remote clients rejected, and the caller's process ID read from the pipe.
- **Authenticode checks** (`WinVerifyTrust`) on callers.
- **Toast notifications** and the notification area through Tauri, with WebView2 for the UI.
- **Code signing:** a certificate or Microsoft's Trusted Signing service. Without signing, SmartScreen warns on install and the caller checks lose their value.

### Linux (later, designed for now)

Secret Service (GNOME Keyring or KWallet), a systemd user service, `SO_PEERCRED` caller checks and a StatusNotifierItem tray icon. `sy-core` has no OS code, so this is an added backend, not a rewrite.

## Licensing

- **Bitwarden:** use the `bw` CLI (GPL-3.0) as a separate program. **Don't link Bitwarden's SDK.** Its license limits use to apps for Bitwarden's own servers (2024 reports say that excludes alternative servers such as Vaultwarden) and forbids selling the result. Re-check the current terms in Phase 0.
- **Tauri, `rmcp`, RustCrypto, `reqwest`:** MIT or Apache-2.0.
- **CI enforces an allowlist** of permissive licenses through `cargo-deny`, so the commercial option stays open.
- **Synapse's own license** is decided at the commercial gate. See [Commercial path](../08-commercial-path.md).

## Risk register

| Dependency | Risk | Effect | Answer |
|---|---|---|---|
| Agent app config formats | Vendors move or rewrite config files | MCP stops routing for that app | Adapters are data. Watch checks for drift daily and on file change. Fixes ship as a catalog update. |
| MCP spec | Auth or transport changes | Gateway fails with some servers | Track `rmcp`. Support stdio and Streamable HTTP. Run conformance tests in CI. |
| Provider auth | Token formats, endpoints and scopes change | Sign-in or refresh breaks | Provider modules are isolated. Health checks catch failures early. Endpoints are config. |
| Employer policy | Org blocks apps or requires approvals, or IT forbids personal tools | Some sign-in options unavailable | Fall back to a `gh` import or an SSO-authorized token. If personal tools are forbidden, the Work MBP runs Watch only, or nothing. |
| Vaultwarden | Security bugs, slow fixes, client features it doesn't support | Vault exposure, sync issues | Not a runtime dependency. Tailscale-only access. Watch tracks its version. Delay Bitwarden client updates if needed. |
| git and `gh` | Behaviour changes | Helper or shim misroutes | Integration tests against the latest git and `gh` on both OSes for every release |
| Windows signing | Cost or availability | SmartScreen warnings, weaker caller checks | Budget for Trusted Signing in Phase 0 |
| WebView2 and Tauri | UI rendering bugs | Cosmetic only | The UI holds no secrets, so a broken UI never leaks |
| Single maintainer | Time and focus | Stalls mid-phase | Each phase is useful on its own. Docs and tests travel with the code. |
